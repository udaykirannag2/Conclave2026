| 2:00–6:00 | *"Where FinOps Breaks for AI"* — Challenges of Token Spend Management | Four concrete reasons this is hard, not just under-invested: **(1) Tagging mismatch** — cloud tagging is infrastructure-first (tag an EC2 instance, it runs for hours, the bill shows whose it is); AI is application-first — a request happens in 50 milliseconds and is gone before you can tag it. Fix: tag at API-call time, inside the application code. **(2) Spend fragmentation** — AI spend splits across vendors: Bedrock $2,000, OpenAI $1,500, Anthropic $800, Pinecone $300 — $4,600 real total, but finance's AWS-only view shows $2,000. Over half the spend is invisible to whoever's supposed to be watching it. **(3) No benchmarks** — cloud has public, known unit prices to benchmark against (a t2.micro is ~$10/month, a c5.large ~$85). Nobody knows what a chatbot *should* cost per user yet — the category's too new, there's no historical data. **(4) Forecasting is guessing** — cloud forecasting is straightforward (spend $100K this month, forecast $100K next month, usually right); AI forecasting isn't — $0 last month, $5K this month, $50K next, because the adoption curve is vertical. Real line from a FinOps leader: *"We went from $10,000 to $100,000 in two months. Nobody predicted it."* |
| 6:00–10:00 | *"Three Things Shape the Bill"* — Primary Drivers of LLM Cost | The formula: **Cost = Request Shape × Usage Scale × Overhead.** **Request shape** = input tokens, output tokens, context-window size — the size of one transaction. **Usage scale** = model tier, request volume, number of model calls — how many transactions, on which model. **Overhead** = retries, agent loops, latency requirements that force costlier models — and overhead is *not* a separate cost bucket, it's a **multiplier** on the first two. A retry doesn't add a flat fee — it reruns the exact same request shape and usage-scale work a second time. Overhead starts at 1.0 for zero waste and climbs with every retry, loop, or forced upgrade. That's why cutting overhead has an outsized effect: it doesn't just remove a cost, it removes a multiplier on everything else. *(This is the mechanical version of the "math that lied" idea from the 15-min draft — same insight, now with the actual formula instead of just the 10x→30x headline. Optional: keep a one-line callback — "that's how 10x user growth quietly becomes 30x cost growth" — to bridge the two if useful.)* |
| 10:00–10:30 | Name the framework | *"The framework you're taking home: Track, Trim, Tame."* State it once, cleanly — track your spend, trim the waste, tame what can spiral on its own. |
| 10:30–14:30 | Stage 1 — Track: Visibility ("See where every dollar of AI spend actually goes") | The course's own **INFORM framework**: Ingestion → Normalization → Allocation → Showback — the four-layer stack that turns raw usage into a number a team can act on. Tag at the **API-call level** (team / app / cost-center / environment), not the infrastructure level — this is the direct fix for the tagging mismatch from segment 2. **Anomaly detection** across three types: usage anomalies (spikes/drops), model anomalies (unexpected tier changes), cost anomalies (per-unit cost shifts). **Showback dashboards** — different metrics for CFO vs. team lead vs. engineer — because showback is what drives optimization; you can't ask a team to cut a cost they can't see. |
| 14:30–19:30 | Stage 2 — Trim: Optimization Levers ("Cut the bill without cutting capability") | The big three, in impact order: **Model choice** — right-size the model to the task, don't default to frontier for everything. **Pricing model** — on-demand vs. committed capacity vs. batch; run the breakeven math before committing (`commitment cost ÷ on-demand cost = breakeven utilization %`). **Prompt caching** — 90% discount on repeated/cached context; breakeven is almost immediate, typically inside the second request against the same context. Combined, these three levers cut costs **80%+** in the course's own modeling. One more trap worth a line: don't assume the published price is the real cost — egress, throttling/retries, and regional pricing variance hide an extra 20–40% for teams that never audited it. |
| 19:30–25:30 | Stage 3 — Tame: Guardrails & KPIs ("Build guardrails to detect and act") | The centerpiece story, straight from the course: a support agent answering one billing question, re-sending its full context at every step — 8 API calls, 21,500 tokens total, versus ~1,000 tokens for a single direct call. **The agent cost 21.5x more** — before a retry loop pushes it past 50x, or an unterminated hallucination loop makes it unbounded. Five guardrails that fix it: **max depth** (a support agent rarely needs more than 3–5 steps), **max tokens per task** (not per call — per task), **retry limit** (3 tries, then escalate), **timeout**, and an **explicit fallback** — a clean "I don't know, escalating to a human" state. The KPI shift this forces: measure **cost per task/per outcome**, not cost per call — that's the unit that lets you compare human work, machine work, and hybrid work on the same basis. Compliance line for the room: in healthcare and finance, guardrails aren't optional — you need to be able to audit what an agent did and what it spent. |

## Cold Open script (Option B, unchanged from the brainstorm)

1. *Chat prompt 1:* "Before I start — drop it in the chat: how many of you are building or managing an AI application right now?" *(pause, acknowledge responses)*
2. *Chat prompt 2:* "Now the real question: how many of you know exactly what it costs to run that application?" *(pause — expect the number to visibly drop)*
3. *Land it:* "That drop-off is normal. Most organizations right now are struggling to know what their AI spend actually is — and even harder, what value it's actually delivering back to the business."
4. *Name the term:* "That gap has a name that's getting a lot of attention right now: **Tokenomics**."
5. *Borrow the authority without the citation:* "That's not just a buzzword — there's already a formal definition for it: the discipline of converting capital into AI, then consuming AI services efficiently enough that they actually drive business value." *(paraphrased from the FinOps Foundation's "Certified FinOps for AI" course definition — decision made: don't name the Foundation on stage.)*
6. *Translate for the room:* "In plain terms: it's a framework — a practice — for making sense of your AI spend, and figuring out the value it's providing your business."
